# 05 UI 设计系统

版本：v0.1

## 1. 设计目标

账然 UI 应表现为：

- 简洁
- 清晰
- 轻量
- 有财务产品的可信感
- 信息密度适中
- 不制造不必要的操作按钮

视觉以 `prototype/账然_UI原型.html` 为主要参考。

HTML 原型定义“视觉目标”，本文件定义“视觉规则”。

## 2. 设计原则

### 2.1 内容优先

金额、分类、商户、时间等信息优先级最高。

### 2.2 状态明确

Pending、Confirmed、Ignored 等状态应有明显但不过度的视觉区分。

### 2.3 可点击区域明确

用户应该容易判断：

- 哪些可以点
- 点了会发生什么

### 2.4 避免重复操作

如果字段本身可点击编辑：

不要再增加一个重复的“编辑”按钮。

## 3. Design Tokens

Token 取值的权威来源：`prototype/账然_UI原型.html` 中 `:root` 定义的 CSS 变量与其中使用的色值。

落地要求：

- 必须一次性提取为 `ui/theme/Color.kt`、`Typography.kt`、`Shape.kt`、`Dimens.kt`，不允许在页面中内联散落色值与尺寸。
- 原型中的渐变与玻璃效果（glass）属于视觉参考，实现时必须收敛为少量可复用 token，不得逐页复制内联样式。
- 原型中的示例数字、示例账户名、示例文件名不是设计 token，不作为实现依据。

Token 集合：

```text
Color
├── Background
├── Surface
├── SurfaceVariant
├── Primary
├── Secondary
├── TextPrimary
├── TextSecondary
├── TextDisabled
├── Divider
├── Expense
├── Income
├── Transfer
├── Warning
└── Error
```

## 4. Typography

至少定义：

```text
Display
Headline
Title
Body
Label
Caption
Amount
```

金额应提供专用 Typography。

Typography 取值同样以原型 CSS 为准，并集中定义在 `Typography.kt`；禁止在页面内使用 `fontSize = 13.sp` 之类的临时值。

## 5. Spacing

统一使用 spacing token：

```text
xs
sm
md
lg
xl
xxl
```

禁止页面中随意出现大量魔法数字。

## 6. Shape

统一：

- Card radius
- Dialog radius
- Button radius
- Input radius
- Chip radius

## 7. Card

常见：

- Home summary card
- Budget card
- Transaction card
- Pending card
- Auto ledger status card

Card 应保持一致：

```text
padding
radius
background
border/elevation
```

## 8. Row

统一 Settings / List Row。

### 普通 Row

```text
Icon | Title | Supporting | Value / Chevron
```

### Switch Row

```text
Icon | Title | Description | Switch
```

### Clickable Row

整个 Row 可点击。

## 9. Amount

金额显示统一：

```text
¥ 1,234.56
```

金额颜色由交易类型决定，但不能仅依赖颜色传达语义。

## 10. Badge

用于：

- Pending
- Confidence
- Source
- Reason

Badge 不应过度使用。

## 11. Button

主要操作：

- Primary
- Secondary
- Text
- Destructive

同一页面不要出现多个竞争性的 Primary CTA。

## 12. Bottom Navigation

MVP：

```text
首页
统计
记一笔
预算
我的
```

“记一笔”可以具有更高视觉权重，但不改变整体导航结构。

## 13. Dialog

用于（居中或底部卡片式对话框，含确认语义或需要输入）：

- 自定义分类（输入分类名）
- 删除确认
- 恢复模式选择
- 清空数据 / 清空日志确认
- 高风险操作

## 14. Bottom Sheet

适用于（选择列表与轻量操作）：

- 分类选择
- 账户选择
- 时间选择
- 筛选
- 规则测试结果

形态分工（避免同一交互两种形态）：

- “重复判断”是**整页**（`DuplicateReviewScreen`），不是 Dialog：它需要并排对比两条记录并承载两种结论，Dialog 空间不足。
- 选择类（分类 / 账户 / 时间）统一使用 Bottom Sheet。
- 确认类（删除、清空、恢复模式）统一使用 Dialog。

## 15. Loading

不要用全屏阻塞式 Loading 处理普通数据库读取。

优先：

- skeleton
- inline loading
- button loading

每个 Screen 的 Loading 形态由 `06` 逐页定义。

## 16. Empty

Empty State 必须说明：

1. 当前没有什么
2. 为什么可能为空
3. 下一步可以做什么

## 17. Error

Error State：

- 说明问题
- 给出可操作的恢复方式
- 不显示技术堆栈

## 18. Accessibility

必须考虑：

- touch target
- content description
- contrast
- font scaling
- screen reader

## 19. 动画

动画：

- 短
- 克制
- 服务于状态变化

不要为了“看起来高级”加入大量动画。

## 20. 页面视觉规则

页面应优先采用：

```text
Screen
 ├── Top App Bar
 ├── Content
 │   ├── Section
 │   ├── Card
 │   └── Row
 └── Bottom Navigation / CTA
```

具体页面布局、字段范围、状态与交互由 `06_UI组件与页面规格.md` 定义。

## 21. 展示标签映射

领域字段名是权威（见 `03` §5），UI 标签必须按下表映射，不得自行发明同义标签：

| 领域字段 | UI 标签 |
|---|---|
| `merchant` | 商户 / 收款方 |
| `amountMinor` | 金额 |
| `type` | 类型（支出 / 收入 / 转账 / 退款） |
| `categoryId` | 分类 |
| `accountId` | 账户 |
| `sourceAccountId` / `targetAccountId` | 转出账户 / 转入账户 |
| `transactionTime` | 时间 |
| `note` | 备注 |
| `source` | 来源 |
| `state` | 状态 |
| `confidence` | 置信度 |
| `engineVersion` | 引擎版本（展示用名，不写 Parser Version） |
| `matchedRuleId` | 命中规则 |
| `externalTransactionId` | 交易单号 |
| `evidenceId` | 解析证据 |

禁止：

- UI 出现领域模型中不存在的字段（例如独立的“支付方式”对象）。
- 同一领域字段在不同页面使用不同标签。
