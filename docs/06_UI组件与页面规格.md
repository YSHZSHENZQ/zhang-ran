## 3. 组件原则

组件必须：

- 接收最小必要参数
- 不持有业务数据源
- 不直接访问 ViewModel
- 不直接访问 DAO
- 不包含产品业务规则
- 不自行计算相似度、置信度、状态或统计口径（只展示 Domain 给出的结论）

## 4. 页面清单

### 4.1 HomeScreen

目的：展示当前账务概况和最近交易。

入口：App 启动 / Bottom Navigation。

内容：

- 本月支出
- 本月收入
- 本月结余
- 待确认数量
- 最近交易
- 自动记账状态

操作：

- 点击交易 → Detail
- 点击待确认 → Pending
- 点击自动记账状态 → AutoLedger
- 点击搜索图标 → Search
- 点击“记一笔” → Add

口径要求：

- 金额格式统一 `¥ 1,234.56`。
- 本月结余 = 本月收入 − 本月支出；不含转账；退款按 `02` §14 冲减支出。
- 不展示未定义指标（原型的 “RECORDS 128” 无口径，不实现）。

状态：

- Loading：卡片骨架屏
- Empty：无交易时展示空态（说明“还没有记录”+ 引导记一笔或检查自动记账）
- Error：读取失败时展示 Error State + 重试

### 4.2 StatsScreen

内容：

- 月度收支（本月消费 / 收入 / 结余）
- 展示指标：日均支出、最高单日支出、记账笔数（口径见 `02` §14）
- 分类占比（环形图 + 图例）
- 按天趋势（**本周 7 天柱状图，可横向切换上一周/下一周**）
- 月份切换（右上角显示当前月，可切换到历史月份）

规则：

- 统计口径以 `02` §14 为准（Pending / IGNORED / DELETED 不计入；Transfer 不计入收支与消费；Refund 冲减退款发生月）。
- 趋势图与分类占比数据由 Domain 提供，UI 不做二次计算。
- 统计页**只展示** `02` §14 已定义的指标（月度消费/收入/结余、日均支出、最高单日支出、记账笔数、
  分类占比、按天趋势）；不得新增未定义指标（如“环比增长”“消费排名”等）。
- 趋势粒度：**按天**，单屏显示一周（周一至周日，7 柱）；支持左右滑动切换到相邻周。
  跨月时只显示该周内**属于当前查看月**的天数为数据，其余天数为 0（不得跨月取数）。
- 月份切换：右上角胶囊显示当前查看月（如「2026 年 10 月」），点击可选择历史月份；
  默认为设备时区当前月。**不提供未来月份**。
- 三项展示指标（日均/最高单日/笔数）口径见 `02` §14，由 Domain 计算。

状态：Loading（骨架）/ Empty（当前查看月无数据）/ Error（重试）。

### 4.3 AddTransactionScreen

字段：

- 商户
- 金额
- 类型
- 分类
- 账户
- 时间
- 备注

类型：

- 支出
- 收入
- 转账（选中后显示转出账户 / 转入账户，隐藏分类）
- 退款（选中后必须选择原交易；找不到原交易时允许提交，该笔进入 Pending，reason = REFUND_UNCERTAIN）

分类：

- 按当前类型（支出 / 收入）展示对应 `Category.type` 的分类网格。
- 选择“其他” → 自定义分类弹窗（收入与支出均适用，规则见 `02` §9）。

时间：

- 选择器选项为“现在 / 今天上午 / 今天下午 / 昨天晚上 / 自定义”。
- 这些是**展示用快捷选项**；落库必须是绝对时间（`transactionTime` = UTC epoch millis），并按 `transactionTimeZone` 记录时区。
- 禁止把“今天上午”这类文案写入交易时间字段。

保存后：

- 支出 / 收入 / 转账 / 退款 → `CONFIRMED`。
- 退款缺原交易 → 进入 Pending（reason = REFUND_UNCERTAIN）。
- 保存后返回首页；表单重置。

状态：Content / Submitting（按钮 loading）/ Failure（字段级错误提示）。

### 4.4 BudgetScreen

内容：

- 月度总预算
- 分类预算
- 使用量
- 剩余预算

交互：

- 点击预算卡片 → 编辑月度总预算
- 点击分类预算行 → 编辑该分类预算
- 支持“添加分类预算”
- 不提供顶部重复“编辑”

规则（见 `02` §12、`03` §9）：

- 总预算与分类预算互相独立，不叠加校验。
- 超预算仅视觉提示（颜色 + “已超支 ¥X”）。
- Pending 不占用额度；Deleted 回滚；Refund 释放额度。

状态：Loading / Empty（未设置预算）/ Error。

### 4.5 MineScreen（“我的”）

目的：设置入口与权限状态。

内容：

- 权限状态（按当前工作模式展示，见 `02` §19）
- 自动记账总开关
- 自动记账状态入口 → AutoLedger
- 待确认记录入口（显示数量）
- 记账提醒开关
- 暗色主题开关
- 数据管理入口：分类管理 / 账户管理 / 预算管理 / 解析规则 / 数据备份与恢复 / 捕获日志
- 关于账然

规则：

- 自动记账总开关只在“我的”页出现一次，AutoLedger 页不得再放一个开关。
- 权限状态行按工作模式渲染；缺失权限显示“未授权”并可跳转 Onboard。
- 暗色主题与记账提醒为设置项，存 DataStore，并进入备份的 `settings.json`。

### 4.6 TransactionDetailScreen

展示：

- 金额
- 商户
- 类型
- 分类
- **支付方式**（该行即账户的展示位；`03` §8：支付渠道是账户属性，不是独立对象）：
  `TRANSFER` 时展示「转出账户 / 转入账户」两行；`REFUND` 时额外提供原交易入口。
- 时间
- 备注
- 来源
- 状态
- 置信度
- 引擎版本（`engineVersion`）
- 命中规则（`matchedRuleId`）
- 交易单号（`externalTransactionId`）
- 原始捕获证据

交互：

- 点击字段 → 编辑该字段（商户、金额、类型、分类、支付方式、时间、备注均为字段级编辑）
- 删除记录（需二次确认，文案必须说明可恢复窗口，不得写“删除后无法恢复”）

禁止：

- 不存在任何“编辑交易”聚合弹窗（一次修改多个字段会与字段级编辑构成双入口）。
- 不得同时展示「账户」与「支付方式」两行——二者是同一对象（`03` §8）；非转账情形本页统一用「支付方式」作标签（`TRANSFER` 的两行按 `05` §21 用「转出账户 / 转入账户」）。

状态：Content / Submitting / Error。

### 4.7 PendingScreen

展示：

- Pending 记录
- Pending reason（多个 reason 时展示严重度最高的一个，详情可见全部）
- confidence
- 来源
- 时间
- 金额

操作（按 reason 决定，见 `02` §5）：

| reason | 可用操作 |
|---|---|
| POSSIBLE_DUPLICATE | 查看重复 / 忽略 |
| 其他 | 编辑后入账 / 忽略 |

规则：

- 所有 Pending 行都提供“查看原始捕获信息”。
- 忽略后该记录变为 IGNORED，保留证据，可从捕获日志恢复，不计入统计。
- 不支持批量处理（v0.1）。
- 排序：按捕获时间倒序。
- 无超时自动消失机制。

状态：

- Loading
- Empty：`所有记录已处理完毕`（含下一步引导）
- Error

### 4.8 PendingEditScreen

> **本页不实现**（单 APK / D3-功能）：Pending 的确认与编辑由**内嵌采集核心的记账面板（含悬浮窗）**承担，以维持"每个业务对象只有一个编辑入口"（`AGENTS.md` §7、`04` §20 第 2 条）。下方规格保留作为**交互参考**与将来自建编辑页时的依据。

字段：

- 商户
- 金额
- 类型
- 分类（按所选类型展示对应分类；含“其他” → 自定义分类弹窗）
- 账户（类型为转账时展示转出 / 转入账户）
- 时间（绝对时间输入，禁止相对文案落库）
- 备注

底部：

- `保存并入账`

保存后：

- `PENDING → CONFIRMED`
- 仅将用户**实际修改过**的字段写入 `FieldEdit`（字段级保护）
- 保存后一律置 `confirmedByUser = true`（编辑即确认，见 `03` §11）

状态：Content / Submitting（按钮 loading）/ Failure。

### 4.9 DuplicateReviewScreen

形态：**整页**（不是 Dialog，见 `05` §14）。

展示：现有记录 vs 新捕获。

比较（展示项由 Domain 提供，UI 不自行计算）：

- merchant
- amount
- time
- externalTransactionId
- source

操作：

- 这是同一笔 → 新候选置 `DUPLICATE`，保留证据与用户决定，返回 Pending
- 这是两笔不同交易 → 进入 PendingEdit 继续编辑入账

状态：Content / Error（证据缺失时给出说明）。

### 4.10 AutoLedgerScreen

展示：

- 自动记账总状态（含“疑似失效”提示，见 `02` §21）
- 微信
- 支付宝
- 当前工作模式与采集能力
- 权限状态
- 最近识别记录

操作：

- 测试自动记账
- 查看日志 → Logs
- 解析规则 → Rules
- 待确认 → Pending

规则：

- 自动记账总开关不在本页（在“我的”页）。
- 测试自动记账的结果必须展示链路阶段（Capture → Adapter → Normalize → Confidence → Dedup → Decision）与最终态。

状态：Loading / Empty（无最近记录）/ Error。

### 4.11 OnboardScreen（权限引导）

目的：按所选工作模式引导用户完成**本应用**（内嵌采集核心已随包安装）所需权限。

内容与步骤（按 `07` §9 的权限矩阵渲染，只展示当前模式需要的步骤）：

| 工作模式 | 步骤 |
|---|---|
| ~~LSPosed 模式~~ | **内嵌后不支持**（已剥离 Xposed 身份，且目标设备无 Root）；引导页不得展示该模式 |
| 通知渠道（基础） | 1. 通知权限（`POST_NOTIFICATIONS`）2. 前台服务与识别服务可用性确认 3. `INTERNET` 仅本机回环说明 |
| OCR 模式 | 1. 无障碍或 Shizuku 授权 2. 截图能力确认 3. 通知渠道状态检查 |
| 短信模式（可选） | 1. 短信读取权限（`RECEIVE_SMS` / `READ_SMS`） |
| 悬浮窗 / 记账面板（可选） | 1. 悬浮窗权限（`SYSTEM_ALERT_WINDOW`） |
| 通用 | 电池优化（建议项，可跳过） |

操作：

- 前往授权（跳系统设置，指向**本应用**的权限页）
- 跳过 / 稍后再说
- 完成

规则：

- 不得展示与当前模式无关的权限步骤。
- 必须写清授权主体是**本应用**（单 APK 下权限均由账然 APK 自身声明，`02` §18.1、`07` §9）。
- 授权返回后必须刷新权限状态。
- 首次完成引导后，不得在每次启动强制弹出。

状态：Content / PermissionDenied（给出重试与说明）。

### 4.12 CategoriesScreen

展示分类列表，按 `type` 分为“支出分类 / 收入分类”两组。

操作：

- 添加
- 点击分类 → 编辑（名称、图标、启用 / 禁用）
- 启用 / 禁用
- 调整顺序（`sortOrder`）

规则：

- 不提供物理删除；已被交易引用的分类只能禁用。
- 同一 `type` 下名称唯一，重名必须提示。
- 分类页不提供“自动分类规则”编辑入口；规则统一在 RulesScreen 编辑，本页只提供跳转入口。

状态：Loading / Empty（仅系统分类时也有内容）/ Error。

### 4.13 AccountsScreen

展示账户列表（现金 / 银行卡 / 第三方 / 信用卡分组展示）。

操作：

- 添加（名称、类型、渠道、尾号、是否默认）
- 点击账户 → 编辑
- 启用 / 禁用
- 调整顺序

规则：

- 账户不得物理删除，只能禁用。
- 账户即支付方式（`03` §8）；不提供独立的“支付方式”列表。
- 默认账户唯一。

状态：Loading / Empty / Error。

### 4.14 RulesScreen

展示：

- ruleId
- priority
- enabled
- direction
- include
- exclude
- engineVersion

操作：

- 添加规则
- 点击规则 → 编辑（include / exclude / direction / priority / enabled）
- 规则测试

规则：

- 只有一个规则对象；分类页不得再提供第二套规则编辑。
- priority 数值越小优先级越高（见 `02` §16）。
- 规则测试：输入一条捕获数据，展示命中规则、匹配关键词、被拒绝关键词与解析字段；保存规则后测试结果写捕获日志（状态 `RULE_TEST`）。

状态：Loading / Empty（无自定义规则时展示系统规则）/ Error。

### 4.15 BackupScreen

功能：

- 创建备份（生成 `zhangran-backup-v1-<yyyymmdd>.zip`）
- 恢复备份
- 自动备份（开关 + 频率）
- 查看备份格式版本
- 查看最近备份列表（文件名 + 时间 + 大小）
- 删除某个备份
- 危险操作：清空所有数据

恢复模式：

- Merge
- Replace
- Settings Only

规则：

- 恢复必须走 `02` §17 的冲突规则与失败原子性。
- 恢复完成后展示恢复报告（新增 / 更新 / 冲突 / 跳过）。
- 清空所有数据需二次确认，且必须提示“建议先备份”。

状态：Loading / Empty（无备份）/ Error（导入失败提示）。

### 4.18 AboutScreen

展示：

- 版本
- 开源信息
- 隐私说明
- License

规则：

- 版本号必须取应用真实版本（v0.1），不得硬编码为其他版本。
- 因 v0.1 **产品范围决定不提供**检查更新 / 打开 GitHub / 发送邮件反馈等网络入口（与权限无关：账然已声明 `INTERNET` 用于本机回环识别，见 `02` §18.1）
- 隐私说明必须与 `02` §18 一致，并按单 APK 口径说明用途：可写"`INTERNET` 仅用于与本机识别服务的回环通信、账务数据不出本机"，**不得**写"不申请网络权限"或"整个方案不联网"
- 若展示采集核心信息，必须写清其**来源与许可**（AutoAccounting，GPL-3.0，内嵌组件，仅自用）

## 5. 页面统一状态

每个 Screen 必须定义并实现：

```text
Loading
Content
Empty
Error
```

需要异步写入的页面（Add / PendingEdit / Backup 恢复 / 详情编辑 / 设置项）额外定义：

```text
Submitting
Success
Failure
```

约束：

- Loading 优先使用骨架屏或 inline loading，不使用全屏阻塞。
- Empty 必须包含“当前没有什么 / 为什么可能为空 / 下一步可以做什么”三要素。
- Error 必须给出可操作恢复方式，不显示堆栈。
- 所有页面必须处理 Android 返回行为与进程重建后的状态恢复。

## 7. Prototype 原则

HTML 原型：

- 用于确认视觉
- 不直接作为 Android 运行代码
- 不通过 WebView 作为正式 UI

明确不作为依据的内容：

- 原型中的示例数字（金额、笔数、百分比、`待确认 6`、`118 笔自动入账`、`RECORDS 128` 等）
- 原型中的示例文件名（`zhangran_20240628.db` 等旧格式名）
- 原型中的示例账户 / 支付方式列表与分组
- 原型中未被任何入口触发的死代码（例如“编辑交易”聚合弹窗）

正式实现使用 Compose。

## 8. 统一交互原则

普通字段：

> 点击字段本身编辑。

新增：

> 使用“添加”。

危险操作：

> 使用明确按钮 + 二次确认。

不要：

> 字段可点击 + 旁边再放一个“编辑”。

同一业务对象不得有两个编辑入口：

- 分类只在 CategoriesScreen 编辑
- 规则只在 RulesScreen 编辑
- 交易字段只在详情页 / PendingEdit 做字段级编辑
- 账户只在 AccountsScreen 编辑
- 自动记账总开关只在 MineScreen

## 9. 页面验收

每个页面至少检查：

- 与原型结构一致（视觉）
- Typography 一致
- spacing 一致
- clickable 区域正确
- loading/empty/error 完整
- 字段标签与 `05` §21 的映射表一致
- 无不存在于领域模型的字段
- 无重复编辑入口
- Android 返回行为正确
- 屏幕旋转/进程重建后状态合理
- 无直接 DAO 访问
- 未自行计算相似度 / 置信度 / 状态
