## Outcome（一句话）

同一笔付款被抓到两次时，账然只算一笔，用户能在「查看重复」里一键判「同一笔 / 两笔」；列表和首页显示的时间与付款页上的时间一致（不再早 8 小时）。

## 防抖口径（Owner 需选）

Owner 原话：「一定时间内的重复金额不需要记入」。冻结规则 `03` §12：窗口 = 交易时间差绝对值 ≤ 180 秒；**禁止仅凭商户 + 金额判重**；不能确定时一律进 Pending，不得自动消失。

- **B（默认）**：第二次抓到的那笔进待确认并标「疑似重复」，**不计入统计**；用户点「同一笔」就丢弃，点「两笔」才正常记。不改冻结规则。代价：要多点一下。
- **A**：同商户 + 同金额 + 同方向、180 秒内的第二次抓取**直接不生成记录**，只在捕获日志留一条「已防抖」。代价：要改 `03` §12.1（单独 docs 提案）；真付了两笔同额同店时会漏记一笔。

下面 AC 按 **B** 写；选 A 时只改 AC-2 的期望（见 AC-2 括号）。

## In

- 捕获级去抖：同一 `packageName + notificationId + postTime` 只留一条捕获、一条记录（`03` §12.1）
- 交易级判重三级（`03` §12.2）落到新捕获上：externalTransactionId → 渠道单号 24h → 语义兜底（同金额、|Δt| ≤ 180 秒、同商户 或 同方向+同账户）
- 条件不全 → `POSSIBLE_DUPLICATE` + PENDING，不计统计
- 待确认列表：POSSIBLE_DUPLICATE 行显示「查看重复 / 忽略」（M3a 只有「忽略」）
- 「查看重复」页：新记录与被比对的老记录并排，各显示商户、金额、方向、时间、来源；底部「同一笔」「两笔」
- 同一笔：新记录 → `DUPLICATE`，写 `DuplicateDecision`，保留候选与证据，不物理删除，不计统计
- 两笔：去掉 POSSIBLE_DUPLICATE reason，回到普通待确认行（确认 / 改完再记 / 忽略）
- 时间显示修正：所有展示交易时间的地方按设备当前时区显示（存储仍为 UTC epoch millis，`03` §5）
